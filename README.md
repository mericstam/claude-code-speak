# claude-speak

Text-to-speech for Claude Code: every reply is read aloud, English with [Kokoro](https://huggingface.co/hexgrad/Kokoro-82M)
and 41 other languages with [Piper](https://github.com/rhasspy/piper) voices, all via
[sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx). The language is picked per sentence. A port of
copilot-cli-speak as a Claude Code mod (plugin name `kokoro-speak`, as `claude-*` names are reserved).

## Backends

Speech runs in a small bridge process, under one of two backends. Each sets itself up on first use in a home of
its own: it installs `sherpa-onnx-node` and `franc-all` with npm and downloads the Kokoro model (~305 MB).
Replies queue until that is done. Each language's Piper voice (~25–115 MB) downloads in the background when the
language is added; its sentences are read by the English voice until it is there.

| Backend | Where it runs | Home | Audio |
| --- | --- | --- | --- |
| `native` | Linux node (also macOS) | `~/.claude-speak` | `paplay`, `pw-play`, `aplay` or `ffplay` on Linux (WSLg works); ffplay on macOS |
| `windows` | WSL only: Windows `node.exe` | `%USERPROFILE%\.claude-speak` | ffplay on Windows (downloaded) |

`/speak backend auto` (the default) picks `windows` on WSL and `native` everywhere else.
On WSL, `/speak backend native` keeps everything inside the distro.

Requirements: `node` and `npm` on the PATH (Node 20+), plus `tar` and `curl`. On native Linux, an audio player
from the list above (`pulseaudio-utils` or `pipewire` on most desktops). For `windows`, Node for Windows with
`node.exe` reachable from WSL.

## Usage

```
/speak                  toggle speak mode (also: on, off)
/speak speed 1.4        0.5–2.0
/speak voice bm_george  English voice: af, af_bella, af_nicole, af_sarah, af_sky, am_adam, am_michael, bf_emma, bf_isabella, bm_george, bm_lewis
/speak lang             languages read besides English, their download state, and all available
/speak lang add german  by code, English name or own name (de, german, Deutsch); downloads its voice
/speak lang add sv alma   ...with a voice of choice
/speak lang voices de   a language's voices and their sizes
/speak lang remove de
/speak backend native   auto | native | windows
/speak say <text>       speak a line now
/speak help
```

Swedish is on by default. Settings are kept across sessions. Replies are read as in copilot-cli-speak: code
blocks skipped (announced once), short inline code read as the word, markdown stripped, capped at 1500
characters. Subagent turns and interrupted turns are not spoken.

### Languages

Arabic, Basque, Catalan, Chinese, Czech, Danish, Dutch, Finnish, French, Georgian, German, Greek, Hindi,
Hungarian, Icelandic, Indonesian, Italian, Kazakh, Kurdish, Latvian, Luxembourgish, Malayalam, Nepali, Norwegian,
Persian, Polish, Portuguese, Romanian, Russian, Serbian, Slovak, Slovenian, Albanian, Spanish, Swahili, Swedish,
Turkish, Ukrainian, Urdu, Vietnamese, Welsh — 130 voices, listed in `hooks/piper-voices.ts`
(regenerate with `python3 make-catalog.py`).

Each sentence is identified with [franc](https://github.com/wooorm/franc), limited to English and the languages
you added. Replies are mostly English, so a sentence leaves English only on clear evidence, and a one-word
sentence ("Done.", "Hej!") takes its neighbour's language. Short sentences can be mixed up between close
relatives (Swedish, Danish, Norwegian) when several of them are added at once.

## How it works

```
hooks/register.ts      the mod: /speak, and a turn.complete hook that spools each reply
bridge/bridge.mjs      first-run setup, then feeds spooled replies to the worker in order
bridge/tts-worker.mjs  adapted from copilot-cli-speak/src: language per sentence, Kokoro or Piper via
                       sherpa-onnx, PCM streamed to the player
hooks/piper-voices.ts  the Piper voice catalog, generated by make-catalog.py
```

The mod copies `bridge/*.mjs` into the backend's home and starts the bridge there. Each reply becomes a JSON file
in `<home>/spool/`. One bridge serves every open session; it exits once no session has written its heartbeat
(`hb-*`) for 45 s. `<home>/status.txt` says `setup: …`, `ready` or `error: …`; `<home>/bridge.log` has the details.

## Development

```bash
claude plugin validate .
claude plugin test .
claude --plugin-dir ~/claude-speak   # load it into a session
```
